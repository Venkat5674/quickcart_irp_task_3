📚 Part E Detailed Conceptual Answers & Analysis

Q1: What is the difference between debouncing and throttling?
Debouncing delays the execution of a function until after a specific amount of quiet time has elapsed since its last invocation. Every time the event occurs before the timer expires, the timer resets.
Throttling limits the maximum rate at which a function can fire, guaranteeing that it executes at most once per defined time window regardless of how many times the event triggers.
Q2: Which suits search suggestions?
Debouncing is ideally suited for search suggestions. When a user is typing a keyword into a search field, we do not want to trigger backend network requests for every single keystroke. Debouncing ensures that the search request is dispatched only when the user pauses or stops typing for a designated delay (e.g. 500 ms).
Q3: Which suits scroll and resize events?
Throttling is best suited for scroll and window resize events. Because users continuously scroll or drag-resize a window, debouncing would only update when scrolling completely halts. Throttling provides a smooth, regular heartbeat of updates (e.g., once every 1,000 ms or 16 ms for 60fps) to calculate scroll positions, lazy-load images, or update parallax effects.
Q4: What is memoization and how does it improve performance?
Memoization is an optimization strategy where the return values of expensive, deterministic function calls are stored in a lookup cache keyed by their arguments. When the function is subsequently invoked with identical arguments, it retrieves the precomputed value directly from cache in O(1) time, completely avoiding redundant CPU-heavy computations.
Q5: What role do closures play in memoization?
In JavaScript, memoization relies on closures to encapsulate the cache object (such as a Map or plain object) within the outer wrapper function's lexical scope. The inner returned function maintains a permanent reference to this private cache across multiple invocations without polluting the global scope or exposing the cache to external tampering.
Q6: What is event bubbling?
Event Bubbling is the default phase of JavaScript's event propagation model where an event triggered on a deeply nested target element propagates (bubbles) upwards through all of its ancestor elements in the DOM hierarchy (from child → parent → body → html → document → window).
Q7: What is event delegation and why is it useful for dynamically created elements?
Event Delegation is an architectural pattern that attaches a single event listener to a shared parent element instead of binding separate event listeners to every individual child. Because events bubble up to the parent, the parent listener can identify the originating child element using event.target.
Dynamic Elements Benefit: When new elements are added dynamically to the DOM at runtime, they immediately inherit event handling from the parent listener without needing manual listener registration or risking memory leaks.
Q8: What does event.stopPropagation() do?
event.stopPropagation() halts the propagation of the current event in the DOM, preventing it from traveling any further up the tree to ancestor elements (or down during the capturing phase). It does not prevent other handlers on the current element itself (which is what stopImmediatePropagation does).
Q9: What is the difference between event.target and event.currentTarget?
- event.target refers to the actual, innermost DOM element that initiated the event (e.g., the specific <button> that was clicked).
- event.currentTarget refers to the DOM element to which the event listener is currently attached (e.g., the parent <div class="product-list"> handling the delegated event).
